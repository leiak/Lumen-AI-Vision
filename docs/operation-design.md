# 运维与治理设计

## 1. 目标

补齐异常停留识别系统从“发现事件”到“处理完成、效果迭代”的运营闭环，覆盖事件终态、告警通知、处理任务、权限审计、隐私治理、跨摄像头去重、样本回流和模型版本管理。

## 2. 事件终态与处理任务

### 2.1 事件状态流转

```text
candidate -> analyzing -> confirmed -> closed
                      \-> rejected
```

| 状态 | 进入条件 | 责任角色 |
| --- | --- | --- |
| candidate | 边缘侧触发事件候选 | 系统 |
| analyzing | 云端开始模型分析 | 系统 |
| confirmed | 模型或人工判定为异常 | 系统、复核人 |
| rejected | 人工确认误报或规则判定不满足异常 | 复核人 |
| closed | 处理任务完成，或低风险事件超过观察期 | 现场处理人、管理员 |

### 2.2 处理任务状态

```text
pending -> processing -> completed -> closed
   \-> overdue -> escalated
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| task_id | string | 任务 ID |
| event_id | string | 关联事件 |
| assignee_id | string | 当前处理人 |
| assignee_role | string | 处理人角色 |
| status | enum | pending、processing、completed、closed、overdue、escalated |
| due_at | timestamp | 处理截止时间 |
| result | enum | on_site_handled、false_alarm、no_action_needed、other |
| comment | text | 处理说明 |
| created_at | timestamp | 创建时间 |
| updated_at | timestamp | 更新时间 |

处理规则：

1. `medium` 事件默认生成复核任务。
2. `high` 事件生成安保或仓储管理员处理任务。
3. `critical` 事件生成立即处理任务，并通知值班管理员。
4. 超过 `due_at` 仍未完成时，任务状态变为 `overdue` 并自动升级。
5. `completed` 事件允许管理员确认后进入 `closed`。
6. `rejected` 事件不需要现场处理任务，但要保留复核记录。

## 3. 告警通知与升级

### 3.1 通知策略

| 风险等级 | 通知对象 | 通知渠道 | 响应要求 |
| --- | --- | --- | --- |
| low | 不通知 | 无 | 仅记录 |
| medium | 复核人员 | 站内通知 | 30 分钟内复核 |
| high | 安保、仓储管理员 | 站内、企业 IM | 5 分钟内响应 |
| critical | 安保、仓储管理员、值班管理员 | 站内、企业 IM、短信、电话机器人 | 2 分钟内确认 |

### 3.2 通知字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| notification_id | string | 通知 ID |
| event_id | string | 事件 ID |
| task_id | string | 处理任务 ID |
| receiver_id | string | 接收人 |
| receiver_role | string | 接收角色 |
| channel | enum | in_app、im、sms、phone_call |
| status | enum | pending、sent、delivered、read、failed、cancelled |
| retry_count | int | 重试次数 |
| sent_at | timestamp | 发送时间 |
| read_at | timestamp | 已读时间 |

### 3.3 升级策略

1. `high` 事件 5 分钟未确认，升级到仓储主管。
2. `critical` 事件 2 分钟未确认，同时升级到值班管理员和运营负责人。
3. 任务超时后自动生成升级记录。
4. 同一事件在同一升级窗口内不重复通知。
5. 所有通知和升级记录可按事件追溯。

### 4.2 角色权限

| 角色 | 查看事件 | 复核事件 | 处理任务 | 配置摄像头 | 配置区域 | 配置阈值 | 管理用户 | 导出数据 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 安保人员 | 是 | 是 | 是 | 否 | 否 | 否 | 否 | 否 |
| 仓储管理员 | 是 | 是 | 是 | 否 | 是 | 是 | 否 | 是 |
| 调度人员 | 是 | 否 | 是 | 否 | 否 | 否 | 否 | 否 |
| 运营人员 | 是 | 是 | 否 | 否 | 否 | 否 | 否 | 是 |
| 算法工程师 | 脱敏后 | 否 | 否 | 否 | 否 | 否 | 否 | 脱敏后 |
| 系统管理员 | 是 | 否 | 否 | 是 | 是 | 是 | 是 | 是 |

### 4.3 权限控制

1. 用户只能访问授权组织下的摄像头、区域和事件。
2. 算法工程师默认只能访问脱敏关键帧。
3. 导出数据必须走审批或按角色限制字段。
4. 事件、任务、模型结果、复核记录使用统一权限模型。
5. 所有读操作记录访问日志，所有写操作记录变更前后值。

### 4.4 审计日志

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| audit_id | string | 日志 ID |
| user_id | string | 操作人 |
| action | string | 操作类型 |
| resource_type | string | 资源类型 |
| resource_id | string | 资源 ID |
| before_value | json | 变更前 |
| after_value | json | 变更后 |
| ip | string | 来源 IP |
| user_agent | string | 客户端信息 |
| created_at | timestamp | 操作时间 |

必须记录的操作：

1. 登录、登出、权限变更。
2. 摄像头、区域、阈值、抽帧策略变更。
3. 事件复核、任务处理、告警确认。
4. 数据导出、关键帧访问、模型调用。
5. 用户和角色变更。

## 5. 隐私与脱敏

### 5.1 处理链路

```text
边缘视频帧 -> 人脸模糊 -> 车牌策略处理 -> 关键帧上传 -> 云端存储 -> 模型推理 -> 页面展示 -> 数据导出
```

### 5.2 处理规则

1. 关键帧生成后立即做人脸模糊。
2. 默认保留车牌用于车辆关联；未授权场景使用车牌哈希或遮盖车牌。
3. 云端不保存未脱敏原图。
4. VL 模型只能访问脱敏关键帧。
5. 算法工程师访问的样本默认脱敏。
6. 数据导出时按角色决定是否展示车牌。
7. 所有脱敏和访问动作记录审计日志。

### 5.3 数据保留

| 数据类型 | 默认保留 | 说明 |
| --- | ---: | --- |
| 原始关键帧 | 90 天 | 优先保存脱敏帧 |
| 事件记录 | 1 年 | 支持运营统计 |
| 审核日志 | 2 年 | 满足追溯 |
| 标注样本 | 按项目保留 | 用于模型迭代 |
| 通知与任务记录 | 1 年 | 支持闭环分析 |

## 6. 跨摄像头去重

### 6.1 去重键

优先级从高到低：

1. `plate_hash + area_group + time_window`
2. `vehicle_type + vehicle_color + direction + time_window`
3. `track_id + camera_id + area_group + time_window`

### 6.2 区域组配置

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| area_group_id | string | 区域组 ID |
| name | string | 区域组名称 |
| camera_ids | list | 组内摄像头 |
| area_ids | list | 组内区域 |
| priority | int | 事件归属优先级 |
| dedup_window_seconds | int | 去重窗口 |

### 6.3 去重规则

1. 同一区域组内，同一车辆在窗口内只保留一个主事件。
2. 主事件由区域优先级和最早触发时间决定。
3. 其他事件作为关联事件保存，不重复告警。
4. 无车牌时使用弱关联，弱关联只用于合并告警，不用于身份认定。

## 7. 样本回流与模型版本

### 7.1 样本回流

```text
事件 -> 人工复核 -> 样本筛选 -> 标注队列 -> 标注审核 -> 数据集版本 -> 训练/评估 -> 模型版本
```

样本筛选优先级：

1. 人工纠正过模型结果的事件。
2. 高风险事件。
3. 低置信度事件。
4. 夜间、雨天、逆光、遮挡等难例。
5. 新摄像头、新区域、新车辆类型样本。

### 7.2 版本管理

| 版本 | 内容 |
| --- | --- |
| dataset_version | 样本范围、标注标准、划分方式 |
| model_version | 模型结构、权重、超参、训练环境 |
| threshold_version | 分类阈值、风险等级阈值 |
| rule_version | 业务规则、区域配置、通知策略 |
| policy_version | 抽帧策略、脱敏策略 |

### 7.3 发布流程

```text
离线评估 -> 小流量灰度 -> 指标对比 -> 全量发布 -> 持续监控 -> 支持回滚
```

发布要求：

1. 离线评估达到当前生产模型指标。
2. 灰度阶段误报率和召回率不劣于生产模型。
3. 全量发布前保留回滚版本。
4. 每个事件结果记录模型版本和阈值版本。
5. 指标下降时自动告警并暂停灰度。

## 8. 运行监控

| 监控对象 | 指标 |
| --- | --- |
| 边缘节点 | 在线状态、视频流健康、推理延迟、丢帧率 |
| 关键帧上传 | 成功率、重试率、队列积压、存储增量 |
| 模型服务 | QPS、延迟、失败率、GPU/CPU 使用率 |
| VL 服务 | 调用量、延迟、失败率、输出解析失败率 |
| 事件平台 | 事件量、风险分布、复核积压、处理闭环率 |
| 通知系统 | 发送成功率、确认率、超时升级数 |

系统级告警：

1. 边缘节点离线超过 5 分钟。
2. 关键帧上传失败率超过 5%。
3. 模型失败率超过 5%。
4. 高风险事件 5 分钟未确认。
5. 复核队列积压超过设定阈值。

## 9. 验收指标

| 指标 | 目标 |
| --- | ---: |
| 高风险事件处理闭环率 | ≥ 95% |
| 告警响应时长 | ≤ 5 分钟 |
| 通知发送成功率 | ≥ 99% |
| 任务超时升级可追溯率 | 100% |
| 权限变更审计覆盖率 | 100% |
| 脱敏链路覆盖率 | 100% |
| 模型发布回滚可用性 | 100% |
