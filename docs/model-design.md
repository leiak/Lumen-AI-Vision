# 模型设计

## 1. 总体思路

系统采用三层模型架构：

1. **边缘轻量模型**：负责车辆检测、区域判断、运动状态识别和关键帧筛选。
2. **云端时空模型**：负责对关键帧序列快速判断是否存在异常停留。
3. **云端 VL 模型**：负责对疑似异常事件生成自然语言描述、行为摘要和原因假设。

三层模型的目标不同：边缘模型追求低延迟和低算力，云端时空模型追求高召回和快速分类，VL 模型追求可解释性和复杂语义理解。

## 2. 模型分层

### 2.1 边缘车辆检测模型

**任务**

识别视频帧中的车辆目标，输出类别、包围框和置信度。

**候选模型**

| 模型 | 优势 | 风险 |
| --- | --- | --- |
| YOLO-Nano | 延迟低，边缘部署成熟 | 对小目标和遮挡敏感 |
| YOLOv8n | 精度与速度较均衡 | 算力要求略高 |
| MobileNet-SSD | 部署简单，兼容性好 | 精度可能不足 |
| RT-DETR 轻量版 | 端到端检测，可尝试 | 边缘部署成本待验证 |

**输出**

```json
{
  "frame_id": "string",
  "timestamp": "2026-09-23T10:00:00+08:00",
  "objects": [
    {
      "track_id": "vehicle-001",
      "category": "truck",
      "bbox": [120, 300, 560, 720],
      "confidence": 0.91
    }
  ]
}
```

**指标**

| 指标 | 目标 |
| --- | ---: |
| 车辆检出率 | ≥ 95% |
| 单帧误检率 | ≤ 3% |
| 边缘单帧推理延迟 | ≤ 50 ms |

### 2.2 区域与停留判断模型

这不是一个独立深度模型，而是“检测模型 + 跟踪 + 业务规则”组成的边缘逻辑模块。

**输入**

1. 车辆检测框。
2. 预定义库门口多边形区域。
3. 连续帧的车辆中心点轨迹。

**核心逻辑**

1. 判断车辆包围框或中心点是否进入库门口区域。
2. 根据连续 N 帧位置变化判断车辆是否静止。
3. 如果静止，启动停留计时器。
4. 如果离开区域或持续运动，重置或暂停计时器。
5. 达到阈值时触发关键帧上传和事件候选。

**状态定义**

| 状态 | 判定条件 |
| --- | --- |
| 未出现 | 区域内没有车辆目标 |
| 进入 | 车辆目标首次进入区域 |
| 移动 | 区域内车辆中心点连续位移超过阈值 |
| 静止 | 连续 N 帧位移低于阈值 |
| 停留超时 | 静止时间超过业务阈值 |
| 驶离 | 车辆目标离开区域或连续丢失 |

### 2.3 边缘关键帧筛选模型

**任务**

从大量视频帧中选出具有分析价值的关键帧。

**推荐组合策略**

1. **事件触发帧**：车辆进入、静止开始、状态变化、超时触发、驶离。
2. **运动检测过滤**：相邻帧差异低于阈值时跳过。
3. **特征相似度过滤**：使用 MobileNet V3 或轻量图像编码器提取向量，过滤高度相似帧。
4. **滑动窗口采样**：在停留过程中按自适应间隔保留少量代表帧。
5. **质量过滤**：过滤严重模糊、过暗、过曝、目标面积过小的帧。

**初始输出**

每个事件候选默认上传 6 到 12 帧，优先包括：

1. 车辆进入区域帧。
2. 车辆刚静止帧。
3. 车门打开或人员出现帧。
4. 中间停留代表帧。
5. 超时触发帧。
6. 驶离前帧或驶离后帧。

### 2.4 云端异常停留分类模型

**任务**

根据关键帧序列判断事件是否属于异常停留。

**候选方案**

| 方案 | 优势 | 劣势 |
| --- | --- | --- |
| 3D CNN，如 SlowFast / I3D | 对时序动作更敏感 | 需要标注数据 |
| 双流网络 | 能同时利用空间和运动信息 | 光流计算成本较高 |
| Video Swin 轻量版 | 时序建模能力强 | 部署成本需要验证 |
| 图像特征 + LSTM/Transformer | 实现简单，可先用关键帧训练 | 细粒度动作识别可能弱于 3D CNN |

**推荐落地路径**

第一阶段先使用“轻量图像编码器 + 时序 Transformer”构建基线模型，原因是它对关键帧稀疏序列更友好，训练和部署成本较低。后续数据充足后，再引入 3D CNN 或双流网络做提升。

**输出**

```json
{
  "event_id": "string",
  "label": "abnormal_stay",
  "score": 0.87,
  "key_segment": {
    "start_frame_id": "string",
    "end_frame_id": "string"
  }
}
```

**标签体系**

| 标签 | 说明 |
| --- | --- |
| normal_pass | 正常通过 |
| normal_stay | 正常停留 |
| abnormal_stay | 异常停留 |
| channel_blocking | 通道占用或堵塞 |
| loading_unloading | 装卸作业 |
| unknown | 无法判断 |

**指标**

| 指标 | 初始目标 |
| --- | ---: |
| 准确率 | ≥ 88% |
| 异常召回率 | ≥ 92% |
| 误报率 | ≤ 15% |
| 单事件推理延迟 | ≤ 2 秒 |

### 2.5 云端 VL 理解模型

**任务**

对判定为异常的事件生成语义描述，帮助人工快速理解“发生了什么”和“为什么可疑”。

**候选模型**

| 模型 | 优势 | 适用点 |
| --- | --- | --- |
| Qwen2.5-VL | 视觉问答和空间定位能力较好 | 适合中文描述和细粒度理解 |
| VideoLLaMA 系列 | 有视频时序理解能力 | 适合多帧行为描述 |
| GPT-4o 等多模态大模型 | 泛化能力强 | 可作为效果对标 |

**输入**

1. 事件关键帧序列。
2. 摄像头名称、区域类型。
3. 停留时长。
4. 边缘检测到的车辆轨迹摘要。
5. 固定提示词。

**输出**

```json
{
  "event_id": "string",
  "summary": "一辆货车在库门口停留约8分钟，期间车门打开，有人员上下车。",
  "behavior": [
    "车辆进入库门口区域",
    "车辆停止",
    "车门打开",
    "人员出现",
    "车辆持续停留"
  ],
  "possible_reason": "疑似等待装卸或异常滞留，需要人工确认。",
  "confidence": 0.78
}
```

**约束**

1. 输出必须基于提供的帧，不得编造车牌、人物身份或明确结论。
2. 识别不到的信息应输出“无法确认”。
3. 描述只用于辅助复核，不作为最终业务结论。
4. 人脸和敏感信息按业务规则脱敏后再送模型。

## 3. 数据与训练设计

### 3.1 数据来源

1. 项目方授权摄像头历史视频。
2. 现场试运行期事件候选。
3. 人工复核结果。
4. 少量主动采集的边界样本。

### 3.2 标注结构

| 字段 | 说明 |
| --- | --- |
| clip_id | 片段唯一 ID |
| camera_id | 摄像头 ID |
| area_id | 区域 ID |
| start_time | 事件开始时间 |
| end_time | 事件结束时间 |
| vehicle_type | 车辆类型 |
| behavior | 行为标签列表 |
| risk_level | 风险等级 |
| reviewer | 复核人 |
| review_result | 正常、异常、无法判断 |

### 3.3 训练集划分

按摄像头和日期做双重隔离，避免同一段视频或同一摄像头场景同时出现在训练集和验证集。

建议比例：

| 集合 | 比例 | 用途 |
| --- | ---: | --- |
| 训练集 | 70% | 模型训练 |
| 验证集 | 15% | 超参和阈值选择 |
| 测试集 | 15% | 最终效果评估 |

### 3.4 难例策略

重点收集以下样本：

1. 正常装卸但停留较长的样本。
2. 短暂停留但存在危险行为的样本。
3. 夜间、雨天、逆光、遮挡场景。
4. 货车、叉车、小车混行场景。
5. 多车同时进入区域的样本。

## 4. 评估方案

### 4.1 模型评估

| 模型 | 指标 |
| --- | --- |
| 车辆检测 | mAP、检出率、误检率、边缘延迟 |
| 关键帧筛选 | 信息保留率、冗余过滤率、事件完整性 |
| 异常分类 | 准确率、召回率、精确率、F1、混淆矩阵 |
| VL 描述 | 事实一致性、关键行为覆盖率、幻觉率、人工可读性 |

### 4.2 业务评估

1. 每天抽检不少于 50 条事件。
2. 高风险事件 100% 复核。
3. 记录漏报事件并回流样本。
4. 每周输出误报 TOP 原因。
5. 每月评估是否需要更新阈值或模型。

## 5. 部署设计

### 5.1 边缘侧

1. 支持主流边缘盒子和边缘服务器。
2. 模型使用 ONNX Runtime、TensorRT 或 OpenVINO 部署。
3. 本地缓存最近关键帧，断网后补传。
4. 模型版本与规则版本由云端统一管理。

### 5.2 云端

1. 时空模型支持水平扩容。
2. VL 模型通过队列异步调用。
3. 模型服务记录输入帧 ID、模型版本、耗时和输出结果。
4. 支持灰度发布和 A/B 评估。

## 6. 迭代路线

| 阶段 | 目标 | 重点 |
| --- | --- | --- |
| M1 | 规则验证 | 只做车辆检测、区域判断、停留计时和关键帧抽取 |
| M2 | 分类模型 | 建立异常停留分类基线 |
| M3 | VL 可解释 | 接入 VL 模型生成事件描述 |
| M4 | 反馈闭环 | 用人工复核结果回流训练 |
| M5 | 场景扩展 | 扩展通道堵塞、排队异常、装卸异常等场景 |
