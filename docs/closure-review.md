# 项目闭环核查

## 1. 结论

当前项目在“识别 — 分析 — 事件 — 复核 — 样本回流”的主链路上已经基本闭环。业务设计、模型设计、数据设计、API 设计和路线图之间可以相互支撑，能够支撑第一阶段落地。

运营与治理闭环已在 `operation-design.md` 中补齐，包括事件终态、告警通知、处理任务、权限审计、跨摄像头去重、隐私处理链路和模型版本运营。

## 2. 已闭环链路

| 环节 | 当前支撑 | 结论 |
| --- | --- | --- |
| 车辆进入 | 业务场景、边缘检测、区域判断、轨迹设计 | 已闭环 |
| 停留判定 | 区域、阈值、静止判断、状态机 | 已闭环 |
| 关键帧抽取 | 触发时机、抽帧策略、帧角色、上传接口 | 已闭环 |

| 语义解释 | VL 输入、输出、约束、延迟指标 | 已闭环 |
| 事件存储 | 摄像头、区域、轨迹、关键帧、事件、模型结果 | 已闭环 |

## 3. 尚未完全闭环的点

### 3.1 事件终态规则不足

当前事件状态包含 `candidate`、`analyzing`、`confirmed`、`rejected`、`closed`，但没有明确什么时候允许从 `confirmed` 进入 `closed`。

建议补充：

1. `candidate`：边缘上报后生成。
2. `analyzing`：云端模型开始处理。
3. `confirmed`：模型或人工判定为异常。
4. `rejected`：复核为正常或误报。
5. `closed`：高风险事件完成现场处理反馈，或低风险事件超过保留观察期。

### 3.2 告警与处理任务缺失

系统定义了风险等级，但没有说明告警如何通知、通知给谁、如何确认、如何升级。

建议补充：

1. `medium` 事件进入复核列表。
2. `high` 事件触发站内或移动端通知。
3. `critical` 事件触发电话、短信或群机器人通知。
4. 通知后生成处理任务，任务状态为待处理、处理中、已完成、已关闭。
5. 超时未处理时自动升级到上级管理员。

### 3.3 用户、权限和审计不足

目前只有接口层面提到设备 Token 和用户 Token，但缺少完整权限模型。

建议补充：

1. 用户、角色、权限、组织、摄像头可见范围。
2. 安保人员只能查看和复核授权区域。
3. 管理员可以配置摄像头、区域、阈值和通知策略。
4. 算法工程师只能访问脱敏样本和评估数据。
5. 所有查询、复核、配置修改、数据导出都要记录审计日志。

### 3.4 跨摄像头去重不足

当前规则只处理同一摄像头、同一区域内的重复事件。实际库门口可能出现一个摄像头覆盖重叠区域或多摄像头连续覆盖的情况。

建议补充：

1. 按 `plate_or_vehicle_hash + area_group + time_window` 做去重。
2. 若没有车牌，可用车辆类型、颜色、轨迹方向、时间窗口做弱关联。
3. 重叠区域归属优先级由区域配置决定。

### 3.5 隐私处理链路不够具体

业务设计说明了人脸模糊和车牌脱敏，但没有说明在哪个节点执行。

建议补充：

1. 边缘端生成关键帧后先做人脸模糊。
2. 只有在业务授权的场景才保留车牌。
3. 云端存储层不保存未脱敏原图。
4. VL 推理只允许访问脱敏后的关键帧。
5. 数据导出时根据角色决定是否带车牌。

### 3.6 模型运营闭环还需要流程化

当前已经有复核结果回流，但缺少完整的模型版本流转。

建议补充：

1. 样本从复核结果进入标注队列。
2. 标注完成后生成数据集版本。
3. 模型训练后生成模型版本。
4. 离线评估达标后进入灰度。
5. 灰度指标达标后全量。
6. 全量模型保留回滚能力。

## 4. 闭环检查表

| 检查项 | 状态 | 说明 |
| --- | --- | --- |
| 车辆进入能被识别 | 是 | 依赖边缘检测和区域配置 |
| 停留能被计时 | 是 | 依赖轨迹状态和业务阈值 |
| 关键帧能上传 | 是 | 有帧结构、帧角色和上传接口 |
| 事件能入库 | 是 | 数据模型和事件接口已定义 |
| 异常能被分类 | 是 | 时空模型输出标签和置信度 |
| 异常能被解释 | 是 | VL 模型输出描述和行为列表 |
| 人工能复核 | 是 | 有复核字段和复核接口 |
| 复核结果能回流 | 部分 | 需要明确数据集版本和模型版本流程 |
| 告警能触达 | 否 | 需要通知通道和升级策略 |
| 告警能处理 | 否 | 需要处理任务和终态闭环 |
| 权限能控制 | 否 | 需要用户、角色、组织、审计模型 |
| 隐私能保障 | 部分 | 需要明确脱敏节点和访问控制 |
| 效果能评估 | 是 | 已定义业务和技术指标 |
| 系统能迭代 | 部分 | 需要样本、数据集、模型、规则版本管理 |

## 5. 下一步建议

优先补齐以下四件事，项目就能从设计闭环进入可交付闭环：

1. 补充事件终态与处理任务流程。
2. 补充告警通知接口和升级策略。
3. 补充用户、角色、权限和审计日志设计。
4. 补充数据脱敏、样本回流、模型版本和灰度发布流程。
