# 库门口异常停留识别系统业务设计

## 1. 项目定位

本项目面向仓储、制造、物流园区等带有固定出入口和装卸区域的场所，提供“端边云协同 + 小模型初筛 + 大模型理解”的异常停留识别能力。系统不是简单的视频监控回看工具，而是围绕“车辆进入关键区域后是否产生了需要关注的停留行为”完成自动发现、风险分级、语义描述和人工复核。

项目目标是用较低带宽和较低推理成本，把海量连续视频变成少量可处理的高质量事件，并让每个事件具备可解释的业务结论。

## 2. 核心业务场景

### 2.1 车辆在库门口异常停留

车辆驶入库门口检测区域后停留超过允许时间，期间出现车门打开、人员上下车、货物搬运、长时间无人处理等状态变化。系统应记录完整过程并生成风险事件。

### 2.2 正常作业停留

车辆按计划到库门口装卸、签收或等待调度。如果停留时长和作业行为符合业务规则，系统应判定为正常停留，不推送高风险告警。

### 2.3 短暂通过

车辆从库门口经过但未形成实际停留。系统不应产生停留事件，只保留低优先级轨迹记录或直接丢弃。

### 2.4 疑似堵塞或调度异常

多辆车连续在库门口排队、停留时间明显超过历史平均值，或某辆车长时间占用关键通道。系统应提示可能的调度异常或现场拥堵。

## 3. 用户角色

| 角色 | 主要诉求 | 系统提供能力 |
| --- | --- | --- |
| 安保人员 | 快速知道哪里发生了异常 | 实时事件列表、风险等级、关键帧、告警确认 |
| 仓储管理员 | 判断库门口作业是否受阻 | 停留时长统计、拥堵趋势、异常原因描述 |
| 调度人员 | 优化车辆进出和装卸节奏 | 排队长度、超时事件、通道占用分析 |
| 运营人员 | 了解系统准确性和处理效率 | 误报率、漏报率、复核结果、模型效果报表 |
| 管理人员 | 掌握风险和整改情况 | 周期性汇总、异常TOP场景、处理闭环率 |
| 算法工程师 | 持续提升模型效果 | 样本回流、标注队列、评估报告、阈值调优 |

## 4. 事件生命周期

1. **车辆出现**：边缘侧识别到车辆进入预定义库门口区域。
2. **停留开始**：车辆中心点或包围框在区域内持续满足静止条件，系统启动停留计时。
3. **状态观察**：边缘侧持续检测运动变化，包括车辆移动、车门打开、人员出现、装卸动作等。
4. **关键帧抽取**：优先抽取车辆刚进入、刚停止、状态变化、超时触发、驶离前后等帧。
5. **事件候选生成**：达到停留阈值或出现高价值状态变化时，生成事件候选。
6. **云端快速判定**：轻量时空模型判断是否为异常停留。
7. **语义解释**：疑似异常事件交给 VL 模型，生成行为描述和原因假设。
8. **风险分级**：根据停留时长、行为类型、区域重要性、历史规则计算风险等级。
9. **人工复核**：高价值事件进入复核队列，复核结果回流为标注数据。
10. **归档与统计**：事件入库，支持查询、导出、告警闭环和指标统计。

## 5. 业务规则

### 5.1 停留判定

默认规则为车辆在库门口区域内连续静止超过 5 分钟。系统允许按摄像头、区域、车辆类型、时间段配置不同阈值。

建议初始规则：

| 车辆类型 | 默认阈值 | 高风险阈值 | 说明 |
| --- | ---: | ---: | --- |
| 小型车 | 5 分钟 | 10 分钟 | 避免正常落客、临时等待误报 |
| 面包车 | 5 分钟 | 12 分钟 | 关注装卸和人员上下车 |
| 货车 | 8 分钟 | 20 分钟 | 允许正常装卸时间更长 |
| 叉车 | 3 分钟 | 8 分钟 | 关键通道占用应更快提醒 |

### 5.2 状态增强规则

单纯计时容易误报。系统应结合状态变化调整判断：

| 状态 | 影响 | 处理建议 |
| --- | --- | --- |
| 车门打开 | 提高关注度 | 需要判断是否为正常作业 |
| 人员上下车 | 提高关注度 | 结合停留时长和区域规则 |
| 货物搬运 | 通常为作业行为 | 结合工单或装卸区白名单降低误报 |
| 车辆熄火或长时间静止 | 提高风险 | 超过阈值后生成候选事件 |
| 车辆倒车、掉头、长时间堵门 | 高风险 | 触发更高优先级告警 |
| 车辆驶离 | 事件结束 | 保留完整片段用于复核 |

### 5.3 风险等级

建议先使用四级风险：

| 等级 | 含义 | 处理策略 |
| --- | --- | --- |
| 低 | 普通停留、状态无异常 | 只记录，不提醒 |
| 中 | 超时但行为不明确 | 进入复核队列 |
| 高 | 超时且出现人员、车门、装卸等状态变化 | 实时提醒安保或仓储管理员 |
| 严重 | 堵塞关键通道、疑似事故、长时间滞留 | 立即告警并要求处理闭环 |

### 5.4 告警抑制

为避免重复告警，同一车辆、同一摄像头、同一区域内的连续停留事件默认合并。事件结束或超过合并窗口后才能生成新事件。

## 6. 指标体系

### 6.1 业务指标

| 指标 | 定义 | 初始目标 |
| --- | --- | --- |
| 异常停留发现率 | 真实异常事件被系统识别的比例 | ≥ 90% |
| 误报率 | 复核为非异常的事件占比 | ≤ 15% |
| 告警响应时长 | 事件生成到人工确认的平均时长 | ≤ 5 分钟 |
| 处理闭环率 | 高风险事件完成处理反馈的比例 | ≥ 95% |
| 关键事件漏报数 | 人工抽检发现的漏报事件数 | 持续下降 |

### 6.2 技术指标

| 指标 | 定义 | 初始目标 |
| --- | --- | --- |
| 事件识别延迟 | 关键状态发生到事件生成的平均耗时 | ≤ 10 秒 |
| VL 描述延迟 | 异常事件到生成语义描述的平均耗时 | ≤ 30 秒 |
| 上传帧压缩比 | 相对连续视频流的关键帧数据量下降比例 | ≥ 90% |
| 单路日均候选事件数 | 每路摄像头每天产生的事件候选数量 | 可配置，不造成复核过载 |
| 模型准确率 | 异常停留分类准确率 | ≥ 88% |

## 7. 合规与隐私

1. 仅在授权摄像头和授权区域内分析。
2. 现场设置明显的视频采集提示。
3. 人脸区域默认模糊化，除非项目方有明确合法授权和业务必要。
4. 车牌信息按最小必要原则存储，非必要场景可脱敏。
5. 关键帧、事件描述、复核记录设置分级访问权限。
6. 视频原始流默认不长期上传，只上传关键帧或事件片段。
7. 数据保留周期默认建议：原始关键帧 90 天，事件记录 1 年，审核日志 2 年，具体以客户合规要求为准。

## 8. 非功能要求

| 类别 | 要求 |
| --- | --- |
| 可用性 | 云端服务可用性不低于 99.5%，边缘断网时继续本地缓存关键帧 |
| 性能 | 单边缘节点支持至少 8 路 1080p 视频流，具体按硬件确认 |
| 可扩展性 | 支持新增摄像头、区域类型和业务规则，不重构核心模型 |
| 可观测性 | 记录模型耗时、上传耗时、队列积压、失败原因 |
| 安全性 | 传输加密、设备认证、事件访问审计 |
| 可维护性 | 模型版本、阈值版本、规则版本可追溯 |

## 9. 边界条件

1. 光照剧烈变化、雨天、雾天可能影响检测效果。
2. 车辆严重遮挡可能导致状态判断不完整。
3. 摄像头角度不佳时，车门和人员动作可能无法可靠识别。
4. 相邻区域重叠可能导致重复事件，需要区域去重规则。
5. VL 模型描述属于辅助判断，不应直接作为最终法律或责任认定结论。
