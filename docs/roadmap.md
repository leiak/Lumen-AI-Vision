# 落地路线图

## 1. 总体原则

项目采用“先验证规则，再验证模型，再接入大模型，最后闭环运营”的路线。每个阶段都有可交付物和可验证指标，避免一开始直接依赖大模型导致成本不可控。

## 2. 阶段规划

### M0：项目准备，1 周

**目标**

确认试点摄像头、区域边界、业务规则和合规要求。

**主要工作**

1. 选择 2 到 4 路试点摄像头。
2. 绘制库门口区域多边形。
3. 确认车辆类型、停留阈值、高风险阈值。
4. 确认数据授权、存储周期和隐私脱敏要求。
5. 准备边缘设备、对象存储、数据库和基础服务。

**交付物**

1. 试点摄像头清单。
2. 区域配置表。
3. 业务规则表。
4. 数据合规说明。

### M1：边缘链路验证，2 周

**目标**

跑通视频接入、车辆检测、区域判断、停留计时和关键帧上传。

**主要工作**

1. 部署车辆检测模型。
2. 实现多边形区域判断。
3. 实现静止判定和停留计时。
4. 实现事件触发抽帧。
5. 实现关键帧压缩、脱敏和上传。

**验收标准**

1. 车辆检出率不低于 95%。
2. 边缘单帧推理延迟不高于 50 ms。
3. 正确识别车辆进入、静止、超时、驶离。
4. 关键帧上传成功率不低于 99%。

### M2：事件平台与人工复核，2 周

**目标**

建立事件库、复核台和基础统计。

**主要工作**

1. 建立摄像头、区域、轨迹、关键帧、事件、复核数据模型。
2. 实现事件候选入库。
3. 实现事件列表和详情页。
4. 实现人工复核和结果回流。
5. 输出每日误报和漏报统计。

**验收标准**

1. 所有事件可按摄像头、时间、风险等级查询。
2. 高风险事件可进入复核队列。
3. 复核结果可追溯。
4. 能输出每日事件量、误报率、超时事件数量。

### M3：异常停留分类模型，3 周

**目标**

基于关键帧序列训练异常停留分类模型。

**主要工作**

1. 整理不少于 1000 个事件样本。
2. 完成行为标签和风险标签标注。
3. 训练图像编码器 + 时序 Transformer 基线。
4. 与规则引擎结果对比。
5. 建立离线评估和线上灰度机制。

**验收标准**

1. 异常停留召回率不低于 92%。
2. 误报率不高于 15%。
3. 单事件分类延迟不高于 2 秒。
4. 模型输出可按事件追溯。

### M4：VL 语义解释，2 周

**目标**

为疑似异常事件生成可读的中文描述。

**主要工作**

1. 设计 VL 提示词。
2. 接入关键帧和事件上下文。
3. 建立输出结构化解析。
4. 增加脱敏和敏感信息过滤。
5. 建立人工评价集。

**验收标准**

1. VL 描述延迟不高于 30 秒。
2. 关键行为覆盖率不低于 80%。
3. 事实性幻觉率不高于 10%。
4. 不输出无法支撑的身份判断或责任结论。

### M5：反馈闭环与运营，2 周

**目标**

把人工复核结果变成持续优化能力。

**主要工作**

1. 建立难例回流队列。
2. 按周输出误报原因分析。
3. 优化区域、阈值和抽帧策略。
4. 建立模型版本和规则版本管理。
5. 编写运维手册和故障处理流程。

**验收标准**

1. 复核结果可标记为训练样本。
2. 每周能输出效果变化趋势。
3. 阈值调整不需要修改核心代码。
4. 边缘断网后可补传事件和关键帧。

### M6：正式上线，2 周

**目标**

从试点扩展到正式运行。

**主要工作**

1. 扩大摄像头范围。
2. 配置告警通知和值班流程。
3. 建立服务监控和模型监控。
4. 明确事件处理 SLA。
5. 输出上线验收报告。

**验收标准**

1. 云端服务可用性不低于 99.5%。
2. 告警响应时长不高于 5 分钟。
3. 高风险事件处理闭环率不低于 95%。
4. 有完整的权限、审计和数据保留策略。

## 3. 里程碑总览

| 里程碑 | 周期 | 核心交付 |
| --- | ---: | --- |
| M0 | 1 周 | 试点范围、规则、合规确认 |
| M1 | 2 周 | 边缘检测和关键帧链路 |
| M2 | 2 周 | 事件平台和复核台 |
| M3 | 3 周 | 异常停留分类模型 |
| M4 | 2 周 | VL 语义解释 |
| M5 | 2 周 | 反馈闭环 |
| M6 | 2 周 | 正式上线 |

总周期约 14 周，具体可根据摄像头数量、硬件到位时间和客户响应速度调整。

## 4. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 摄像头角度不适合识别车门和人员 | 状态判断不完整 | 先用停留时长和车辆轨迹兜底，必要时调整摄像头 |
| 正常装卸被误报 | 复核压力增加 | 增加装卸区白名单、车辆类型阈值和工单关联 |
| 边缘算力不足 | 延迟高或漏检 | 降低分辨率、减少并发路数、更换边缘设备 |
| 标注数据不足 | 分类模型效果差 | 先用规则引擎，配合主动学习和人工复核回流 |
| VL 描述幻觉 | 影响人工判断 | 限制提示词、结构化输出、人工评价和敏感结论拦截 |
| 数据合规风险 | 项目无法上线 | 明确授权、脱敏、权限和保留周期 |

## 5. 后续可扩展方向

1. 车牌识别和车辆白名单。
2. 工单系统联动。
3. 装卸作业时长分析。
4. 库门口排队和拥堵预测。
5. 多摄像头跨区域轨迹联动。
6. 异常行为自动解释报告。
